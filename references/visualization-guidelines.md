# 可视化与交互设计指南（Knowledge Explorer）

> 用于 Agent 决定是否制作图表、动画或 HTML 学习工具，以及如何验证工具。主流程遵循 `../SKILL.md`。

## 1. 先确认“用户需要看懂什么”

在生成前回答：

1. 用户不理解的对象、关系或过程是什么？
2. 哪个操作（选择、比较、推进、修改参数）能够暴露关键规律？
3. 普通文字或静态图是否已经足够？

没有清楚的学习收益时，不要生成交互式 HTML。用户明确要求 HTML 或模拟时优先满足，但需说明现有材料/环境限制。

## 2. 形式选择

| 知识特点 | 首选形式 | 不要做什么 |
| --- | --- | --- |
| 明确概念及关系 | 可点击概念关系图 | 根据排版需要捏造关系 |
| 有明确先后顺序 | 分步图、时间线 | 把并行步骤画成串行 |
| 多维比较 | 表格、可筛选对比 | 省略可比性前提 |
| 可靠数量数据 | 条形、折线、散点等真实数据图 | 补造数据、改变单位或截断坐标造成误导 |
| 有明确公式或规则 | 参数滑块 + 实时计算 + 解释 | 用视觉变化假装实际计算 |
| 时间或空间连续过程 | 动画/逐帧示意 | 把示意运动当作真实物理仿真 |
| 文字论证/不完整材料 | 分层阅读、重点标注和证据卡 | 为展示效果强行图谱化 |

第一版优先 **1 个主要学习视图 + 少量必要控件**。按钮、滑块、切换不能只用于装饰。

## 3. 常见交互组件的使用约束

### 分步学习
- 有明确阶段划分时采用；每一步有标题、输入、处理/动作、结果或解释。
- 步骤前进和后退必须真正改变展示内容；避免跳过依赖条件。

### 可选对象/概念
- 点击概念后展示其定义、作用、关系与材料依据。
- 无关系数据时改用列表/卡片，不绘制虚构连线。

### 参数与模拟
- 每个参数需要名称、单位、合法范围、默认值与计算规则。
- 计算规则有来源或可验证定义；变化应由输入实际计算得到。
- 若仅用于教学简化，界面明显标注“简化模型”，解释哪些真实因素未考虑。
- 无法从材料建立计算模型时，只展示条件对照，不输出精确仿真数字。

### 自测题
- 可点击作答，立即显示对错及解释；键盘和鼠标可操作。
- 题目来源于讲解内容，避免凭空添加新知识。

## 4. 学习页面视觉规范

- 默认采用**明亮、克制、中性**的阅读风格：浅色背景、白色卡片、深色文字、适量蓝色强调。
- 桌面正文优先 18px 及以上，次级说明尽量不低于 15px，强调清楚的层次与足够行距。
- 保证文字和背景对比度；不要依赖颜色单独区分状态。
- 典型阅读布局应限制内容行宽，重要图示适应屏幕宽度；窄屏不出现横向裁切。
- 标题描述用户学习的问题，不出现“我如何构建页面”“来源第几行”等制作过程信息。
- 实际材料来源与局限可以在相关内容旁展示，制作日志与测试信息则留在交付说明中。

## 5. 单文件 HTML 的最低要求

- 所需 CSS、JavaScript 和必要数据内联，除非用户明确允许联网。
- 页面离线可用，不强制服务器、登录、付费服务、外部字体与 CDN。
- 有一个清晰可用的学习入口、主要内容、必要来源/边界及至少一个真正有用的交互（若任务确实需要）。
- 对材料内容采用安全文本渲染或转义；不要把不可信原文拼进执行逻辑。
- 不要将 API 密钥、令牌或私人文件路径嵌入 HTML。
- 禁止用随机数字、预录曲线和空按钮冒充算法或模型的真实输出。
- 可用时使用 `../assets/html-template.html` 作为起点；也允许按知识类型重构布局，模板不是功能上限。

## 6. 文件交付与后续追问

- 不要求用户掌握 HTML；明确告诉用户打开方式和主要操作。
- 用户要求修改时优先延续当前可访问版本，保留正确内容。
- 页面本地交互不会默认写回 Agent 对话；若有状态依赖，应说明如何反馈参数或导出结果。

## 7. 轻量测试

至少人工或用宿主可用的测试能力检查：

1. 打开页面无语法错误，初始内容显示完整。
2. 逐个操作关键控件，变化与标注相符。
3. 数据、公式、单位和引用与材料一致。
4. 宽屏及窄屏下不出现严重遮挡，正文可读。
5. 无资源加载失败、主动网络请求和危险脚本。

没运行过就说明“未执行浏览器验证”，不声称测试通过。若没有代码执行或文件写入权限，按主 Skill 的降级规则处理。
