# 对话式教学指南（Knowledge Explorer）

> 供 Agent 在准备知识讲解、持续追问和简单学习反馈时按需阅读。优先遵循 `../SKILL.md` 和用户的明确要求。

## 1. 首先理解当前学习任务

从用户的当次请求与实际材料识别：

- **学习对象**：概念、机制、流程、论文、图表、数据或实践方法。
- **最想解决的问题**：是什么、为什么、怎么运行、如何比较、如何应用、哪里不理解。
- **当前理解水平**：以用户提问反映的基础为准，不凭职业、年龄等推测。
- **材料边界**：是否有可读原文、是否需要额外证据、哪些图表或公式尚未读取。

能够直接开始就开始。需要补充资料时，只问影响正确性的最少问题。不要强迫用户先完成测验或学习画像。

## 2. 对话教学的基本节奏

1. **一句话抓住本质**：先给正确且不偷换概念的直观理解。
2. **解释机制**：说明关键对象、输入、动作、输出和成立条件。复杂过程分步讲。
3. **给一个具体例子**：优先采用可验证、能对应原理的例子；例子不是原理本身。
4. **说明重要限制**：哪些情况不适用，哪些属于简化或类比。
5. **留出探索入口**：根据学习难点自然引入图表、示例、交互或继续追问。

避免为了显得通俗而删除条件、用虚构故事替代机制，或把术语解释成另一个更含糊的术语。

## 3. 按问题类型选择讲解方式

| 问题类型 | 首选教法 | 可选增强 |
| --- | --- | --- |
| 定义、术语 | 简短定义 + 与相近概念的区别 | 一张概念卡 |
| 因果和机制 | 输入→规则/过程→结果 | 分步流程图、条件变化演示 |
| 结构或层级 | 部件及其关系 | 概念关系图 |
| 比较与决策 | 相同前提下逐维度对比 | 可筛选表格、情景对比 |
| 数据或数学 | 说明变量、单位和运算规则 | 真实公式驱动的滑块、图表 |
| 论文/原始材料 | 研究问题→方法→结果→边界 | 证据卡、图表解读 |
| 用户仍不理解 | 定位卡点，换角度、拆步骤 | 更具体的反例或小实验 |

简单问题不必完整走一遍教学流程。用户明确希望深入时再逐层展开。

## 4. 隐性知识：从“知道”到“会判断”

对于依赖经验的操作或判断，资料一般只显式说明规则的一部分。不要声称从材料中自动恢复全部专家经验。可采用：

- **案例**：提供一个正常案例，再提供条件相近但结果不同的反例。
- **对比**：指出专家在两个案例之间关注的决定性线索。
- **检查清单**：把能够外化的判断条件写成可检查项。
- **即时反馈**：让用户作出判断，再解释依据及例外。
- **边界说明**：哪些判断仍需现场经验、实验或人工审核。

## 5. 用户连续追问时

- “还是没懂”：先问自己究竟哪个环节不清楚，尝试更短的步骤或另一种类比；必要时只问一个具体问题。
- “能不能看出来”：判断静态图够不够，不够才生成交互。
- “改一个变量会怎样”：说明其变化规则和输入范围；没有可靠公式时不可模拟出确定数值。
- “接着刚才”：复用当前会话中已确认的概念、例子、可访问文件和页面。
- “考考我”：提供 1–3 道检查理解的问题（优先概念应用、反例辨析），给出解释性反馈而非只有对错。

独立 HTML 的滑块、点击位置并不自动同步至对话。如果分析需要用户当前设置，向用户询问或读取实际可访问的状态文件；不要假装知道。

## 6. 事实与表达约束

- 区分：材料明确表达、可复核的计算、模型推断、尚不清楚。
- 涉及原文、图表、数据时优先给可定位依据；引用不能凭空生成。
- 采用受控表达原则：短句、一个词固定一个意思、步骤动作明确；中文无需声称符合正式 ASD-STE100。
- 使用类比要说明类比与真实机制的差别。
- 生成教学问题时确保依据充足，不能将争议性观点设为唯一正确答案。

## 7. 轻量完成检查

完成后问自己：用户现在能否用自己的话解释核心机制？能否举一个合适例子？是否知道结论在哪些条件下成立？是否还有一个具体、容易验证的下一步？

不要向用户展示内部质量检查清单，除非用户明确要求。
